# Status
Implementing.
# Problem and outcome
Replace inaccurate metadata-only mood playlist requests with reusable local audio-derived track profiles. Standard mood mixes must use the available library and saved profiles without an OpenAI request or API key.
# Scope
A managed optional local Essentia/MusiCNN analyser on macOS Apple Silicon, installed in Muse's app-data cache with a pinned self-contained Python runtime and checksum-verified packages/models. Native Rodio decoding supplies bounded sampled mono PCM to a local worker; local/SSH audio never uploads and remote files stay unchanged. Persist versioned profiles keyed to track/source fingerprints; analyse only missing/changed tracks, one at a time, with progress/cancellation and opt-in background continuation. Start with a 20-track pilot. Add local mood ranking over all current profiles, confidence thresholds, artist diversity and fewer-than-20 results when matches are scarce. Add Settings controls and review of sampled profiles with per-mood corrections. Preserve OpenAI album lookup and the existing single audio player. Home mood cards become AI DJ: queue and start a mood session targeting one hour, roughly20 tracks, without saving a playlist. The left navigation retains Create AI playlist and saved-playlist creation.
# Acceptance criteria
- AI DJ replaces only the Home mood section, queues and starts a session using the existing player, targets60minutes with approximately20 tracks (bounded30), and creates no playlist. Short suitable libraries produce a shorter session with a clear message. Saved AI playlist creation remains in left navigation.
- No OpenAI calls or key access during standard mood playlist generation; only current available, freshly profiled library tracks can be selected, max20 with no duplicate track identities.
- Profiles include estimated energy, relaxed/happy/sad/aggressive/danceable/instrumental scores, tempo where available, confidence, analyser version, sample duration and timestamps.
- Unchanged files reuse profiles; changed source fingerprints/model versions are reanalysed. Removed tracks clean up via FK, disconnected SSH sources cannot enter mixes.
- Installation is explicit, cancellable/bounded, integrity checked and separate from system Python. No arbitrary URLs/executables/frontend source paths accepted. Models run locally, with documented non-commercial model licences and offline operation after installation.
- Analysis reads bounded representative audio excerpts through existing local/SSH read-only decoding; no audio copies in the catalog or paid requests. Cancellation/source changes/failures do not commit a partial/incorrect profile and do not affect playback.
- UI offers Install analyser, Analyse 20 tracks, Continue analysis, Cancel, opt-in background analysis, progress/errors and profile review/corrections; mood cards use saved profiles directly and offer analysis setup when needed.
- Native/frontend tests cover cache invalidation, real worker/model contract where installed, ranking exclusions/diversity, no paid call, cancellation/failure and source isolation. Full checks/build pass; record live UI/network gaps.
# Decisions and open questions
Use official Essentia models and published class indices rather than inventing tags from song names. An optional model/runtime pack is larger than Muse, so keep it out of the application bundle; no server installs or remote writes. Model scores are estimates, not calibrated truth; user overrides remain separate from automatic profiles. Initial platform macOS arm64; unsupported platforms show a clear setup error, not a fake heuristic replacement. Parent web UI rules adapted to existing English dark square Metro Muse. Custom natural-language AI playlists are a later extension; existing album AI remains intact.
