# Muse UI rules

Use the [Metro prototype](../design/muse_metro_prototype.html) and existing Muse screens as the visual baseline. Keep the dark, English-language desktop presentation coherent across changed screens. Record intentional departures in the cycle spec.

Reuse the existing UI components, tokens, and navigation patterns. Keep controls keyboard accessible, with visible focus, meaningful labels, and clear loading, empty, and error states. Honor reduced-motion preferences for transitions and visual effects.

For changed UI, inspect the affected screen in the desktop app at a normal and narrow window width. Check keyboard navigation, focus, long text, and relevant loading, empty, and error states. Record the inspection and any limitation in the cycle plan.
